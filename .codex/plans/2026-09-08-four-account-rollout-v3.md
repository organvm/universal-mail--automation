# Four-account mail rollout: coherent operation

This revision preserves every acceptance requirement in v2. It incorporates the
operator's corrections: only the operator clicking Send in Mail.app may send an
email, and the finished system must be coherent and elegant in daily use.

## Intended experience

Mail presents seven plainly named flag views in this order: NOW, ACTION, WAITING,
SCHEDULED, REFERENCE, REVIEW, LATER. Native colors retain their established meanings.
Verify the actual view order; numeric prefixes are not a sorting mechanism. Use
ordered Favorites of the same views if native ordering cannot be changed. Do not
add a competing dashboard or expose provider implementation details in the workflow.

One private evidence queue owns independent obligations and unanswered questions.
One policy decides flag posture and archive eligibility. Existing tools and the
existing recurring owner route through the same transaction authority. Provider
differences remain behind account-bound adapters. Operator updates emphasize
outcomes and necessary decisions, not a stream of internal command results.

## Implementation progress

- Private native inventory and full-message collection now resume across account,
  folder, page, thread, and message boundaries. Raw messages retain attachment bytes;
  collection does not claim semantic review or resolved obligations.
- Authenticated GitHub research resolves exact objects with paginated evidence and
  retains notification provenance. Failed reads do not become empty success.
- Production Gmail, iCloud MOVE, and Outlook immutable-ID archive adapters are
  connected to observe/apply/verify/rollback commands. Production plans require
  coverage, fresh reviewed guards, native override bindings, and canary selection.
- Automated SMTP paths reject transmission even with historical authorization or
  armed environment settings. They require the operator's click in Mail.app.
- Native semantic flag names are visible. Actual ordering is still unverified.
